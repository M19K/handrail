## Round two — the nineteen that were still open

### Critical

**C5. An arrow could appear after Handrail was put away.** `_pointAtTarget`
took no generation token and never re-checked state after its awaits, so an
in-flight `locate()` resolved after the panic hotkey and re-showed the arrow.
Our own comments called this the worst failure this product has.
*Fixed:* `this.epoch` — which already existed and was already bumped by
`_abortRequest()` — is captured at the top of `_pointAtTarget` and checked after
every await, before `point()` and before `emit()`. The `pointing` setting is
re-read too, because switching it off does not bump the epoch.
*Tested:* four unit tests, including one asserting the guard is not so eager it
breaks the normal case.

**C6. Asking in an old thread wrote to the wrong thread.** `_currentThread()`
returned the most recently *updated* thread; the renderer's `openThread(id)`
never reached main.
*Fixed:* the renderer sends `threadId` with every `hr:ask`. `_currentThread()`
resolves it, falls back to most-recent only when unset, and falls back again if
that thread has since been deleted. Same principle as the renderer minting
`turnId`: the renderer owns what only the renderer knows.
*Tested:* five unit tests, plus an end-to-end smoke check that opens an older
thread by clicking its row and asserts the follow-up lands there and not in the
newest one.

**C7. `trackHover` leaked a listener pair per arrow.** Registered from `draw()`,
each pair closing over a label `replaceChildren()` had already detached — so
every mouse move fired N stale `false` calls plus the live `true`: two IPC
messages per move, growing for the whole session.
*Fixed:* the two listeners are registered once at module load against a
module-level `currentLabel` that `draw()` reassigns and clears.
*Tested:* smoke draws six arrows, then counts `setArrowInteractive` calls across
three mouse moves inside the label. Expects exactly one.

**C8. `launchOverlay` leaked a `did-finish-load` listener per call.** The
overlay is created once and never destroyed, so after the first load the event
can never fire again — every tray "Show Handrail" added a listener that was
already dead.
*Fixed:* attached only when the window was just created.

**T1. `threads.json` containing `null` broke boot.** `_readJson` recovered from
unparseable JSON but returned whatever parsed, so `null` set `this.threads` to
`null` and the first `listThreads()` threw — the exact failure the recovery
exists to prevent.
*Fixed:* shape-checked in the constructor. Threads must be an array of objects,
settings must be a plain object, and `updatedAt` is coerced so a missing one
cannot sort to `NaN`.
*Tested:* five unit tests over a throwaway userData directory.

**T2. The watch tick never validated the display.** With an empty `display_id`
the size fallback matched any same-aspect monitor and returned the first, so
every step check for a task on the second monitor silently judged the primary
screen.
*Fixed:* `captureDisplay` returns `matched: 'display_id'|'size'|'fallback'`. The
watch tick stops and emits `unwatched` on `fallback` or an aspect mismatch.
Source selection was extracted as a pure `selectSource`.
*Tested:* seven unit tests, no Electron needed.

**T3. A one-step plan was dumped at the user as raw JSON.** The task branch
needs `steps.length > 1`; a valid one-step plan fell through to the answer
branch, where `res.text` — the whole JSON blob — became the message.
*Fixed:* a new `answerFrom()` synthesises prose from the title and steps. The
product rule that a checklist means genuinely multi-step work is preserved; what
changed is that nothing reaches the user as JSON.
*Tested:* eight unit tests.

### Important

**R1 / R2. `offplan` and `unwatched` were ignored by the renderer.** Both redrew
the checklist identically, leaving something that looked live and would never
advance.
*Fixed:* both set `task.watching = false` and render a plain-English note under
the list. Reopening a step clears it.
*Tested:* three smoke checks and a screenshot (`10-watching-stopped.png`).

**R3. The "Pointing at it on your screen" badge could never clear.** `point` was
emitted on success only.
*Fixed:* one `clearArrow()` used by every path — failure, dismiss, off-plan,
task complete, reset — and the 45s dwell timer calls back into main so it emits
too.

**R4. A numbered list following a bulleted one merged into one `<ul>`.** List
kind was decided once but the item loop accepted both.
*Fixed:* a top-level item of the other kind ends the list and starts the next.
*Tested:* a smoke check on `- a\n- b\n1. first\n2. second`.

**M1. `cancel()` cancelled nothing on the wire.** Escape on a slow 3000-token
vision call left it running and billed; only the reply was discarded.
*Fixed:* an `AbortController` per turn, threaded through `llm.js` into the
adapter's `fetch`. `AbortError` is not reported to the user as a failure.

**M2. `excludeFromCapture` was not re-entrant.** Two overlapping captures each
restored independently, so the first to finish dropped protection while the
other was still capturing — and Handrail appeared in the frame it was meant to
be absent from.
*Fixed:* refcounted, with an idempotent restore.

**M3. The mock bridge shipped in production.** A preload that failed to load
would present a fully working-looking overlay with fabricated threads and a
canned answer.
*Fixed:* excluded from `scripts/package-win.js` as well as the electron-builder
`files` list, and `overlay.js` now fails loudly and visibly when the bridge is
absent. This reverses the earlier "ship what was tested" call — the review's
argument is stronger.

**M4. `watching` was half-wired.** Declared in `DEFAULT_SETTINGS`, given an ipc
branch, never read.
*Fixed:* `startWatching()` honours it.

**T4. `keyHint()` leaked a short key whole.** The head and tail slices overlap
below 13 characters, so `OPENROUTER_API_KEY=short` produced
`Unknown · short••••hort`.
*Fixed:* below that length only the provider is shown.
*Tested:* a unit test and a smoke check.

**T5. `getKey()` deleted the key file on ANY throw.** A keyring that was not
ready yet was indistinguishable from an orphaned blob, and the recovery was
irreversible.
*Fixed:* the file is left alone. `saveKey` overwrites it anyway, the user lands
in onboarding either way, and a failure that turns out to be transient now
recovers on the next launch.

**T6. `friendly()` misclassified provider errors.** `/5\d\d/` matched "5000
tokens"; `/401/` matched "request 401829". These strings are the only diagnosis
the user ever sees.
*Fixed:* codes are matched on digit boundaries, and `err.status` is preferred.
*Tested:* five unit tests, including both false positives.

**T7. `firstSentence` truncated at an abbreviation.** "Use the crop tool, e.g.
the one in the left toolbar." became the label "Use the crop tool, e.g." — and
that label is the only instruction next to the arrow.
*Fixed:* candidate sentence ends that follow an abbreviation or an initial are
skipped.

**Closed 2026-08-09.** `llm.respond()` was the last open item on this page, and
it survived both `/review` and `/qa` because the blocker was structural: the
provider client was constructed inside `_client()`, so there was no seam to test
through without a network call and a funded key. `Llm` takes an optional client
factory now, and that is the only reason it does. The tests cover the request
going out (the screenshot as inline image data, sent first; whole replies in
history rather than titles; history capped; the active-task preamble naming the
checklist and the step number the user sees; the abort signal reaching the
request) and the result coming back (a one-step plan as prose, a runaway plan
capped at twelve, a nonsense `completedStep` refused, schema-ignoring prose shown
rather than a JSON error).

**Nothing on this page is open.** Unit tests stand at 99, smoke at 63, QA at 29.
