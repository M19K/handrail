## OPEN — critical

**C5. An arrow can appear after Handrail is put away.** `src/main/turn.js`
`_pointAtTarget` takes no generation token and never re-checks state after its
awaits. `llm.locate()` takes seconds; during it the user can hit the panic
hotkey, collapse, start a new thread or quit — all of which call `reset()`. The
in-flight locate then resolves and calls `this.point(...)`, re-showing the arrow.
Our own comments call this "the worst failure this product has".
*Fix:* `this.epoch` already exists and is bumped. Capture it at the top of
`_pointAtTarget` and `_pointAtActiveStep`; bail before `this.point()`/`this.emit()`
if it changed.

**C6. Asking in an old thread writes to the wrong thread.** `src/main/turn.js`
`_currentThread()` returns `listThreads()[0]`, which is always the most recently
*updated* thread. The renderer's `openThread(id)` sets `state.openThreadId` and
never tells main. So open a week-old thread, ask a follow-up, and main feeds the
newest thread's history to the model, appends the turn to that thread, then emits
`{type:'thread'}` which rewrites the panel header mid-turn.
*Fix:* send `openThreadId` with `hr:ask` (or add `hr:threads:select`) and have
`_currentThread()` resolve it, falling back to most-recent only when unset.

**C7. `trackHover` leaks a listener pair per arrow.** `renderer/arrow.js` calls
`trackHover(label)` from `draw()` every time, adding two `document` listeners
that are never removed. `draw()` starts with `stage.replaceChildren()`, so stale
handlers close over a detached label whose rect is all zeros — each mouse move
then fires N stale `setInteractive(false)` calls plus the live `true`, sending
**two IPC messages per move** and defeating the "only on change" contract. The
arrow window is never destroyed, so it grows for the session.
*Fix:* register the two listeners once at module load against a module-level
`currentLabel` that `draw()` reassigns.

**C8. `launchOverlay` leaks a `did-finish-load` listener per call.**
`main.js`. The overlay is created once and never destroyed, so after the first
load the event never fires again — every tray "Show Handrail", `onSetupComplete`
and `activate` adds a listener that can never fire. Eleven clicks →
MaxListenersExceededWarning.
*Fix:* only attach when the window was just created, else call `showOverlay()`
directly.

**T1. `threads.json` containing `null` breaks boot.** `src/main/store.js`
`_readJson` recovers from unparseable JSON but returns whatever parsed, so
`null` sets `this.threads = null` and the first `listThreads()` throws. The
comment above it promises the opposite.
*Fix:* validate shape in the caller — `Array.isArray(t) ? t : []`.

**T2. Watch tick never validates the display.** `src/main/capture.js` +
`turn.js`. The ask path checks `captureMatchesDisplay` and disables pointing on
mismatch; the watch tick validates nothing. When `display_id` is empty the size
fallback matches any same-aspect monitor and returns the first — so every step
check for a task on the second monitor silently judges the primary screen.
*Fix:* return a `matched: 'display_id'|'size'|'fallback'` flag from
`captureDisplay`; skip or stop watching when it is `fallback`. Extract source
selection into a pure function so it can be tested without Electron.

**T3. A one-step plan is dumped at the user as raw JSON.** `src/main/llm.js`
The task branch needs `steps.length > 1`; a valid one-step plan falls through to
the answer branch, where `res.text` — the whole JSON blob — becomes the message.
*Fix:* if `parsed.kind === 'task'` in the fall-through, synthesise markdown from
title + steps, or accept `>= 1` and let a one-step checklist render.

## OPEN — important

**R1. `offplan` is ignored by the renderer.** `renderer/overlay.js` `updateStep`
branches on `wrong`/`done`/`active` only. Main emits `offplan`, stops watching
and clears the arrow; the checklist redraws identically. The user is left with
something that looks live and will never advance.

**R2. `unwatched` needs a renderer branch** (the other half of C4).

**R3. The "Pointing at it on your screen" badge can never clear.** `turn.js`
emits `{type:'point'}` only on success. Every failure path, the 45s dwell timer
and the dismiss button clear the arrow silently, so the overlay keeps claiming
it is pointing at something.
*Fix:* emit `{type:'point', rect:null}` wherever the arrow is cleared.

**R4. `renderProse` merges a numbered list following a bullet list into one
`<ul>`.** `renderer/overlay.js` — list kind is decided once but the item loop
accepts both. Input `- a\n- b\n1. first` produces one `<ul>` with three `<li>`.

**M1. `cancel()` does not cancel anything on the wire.** `openrouter.adapter.js`
calls `fetch` with no `signal`, so Escape on a slow 3000-token vision call
leaves it running and billed; the reply is discarded on arrival.
*Fix:* thread an `AbortController` through `respond`/`locate`/`checkStep`.

**M2. `excludeFromCapture` is not re-entrant.** `src/main/windows.js` — two
overlapping captures (watch tick + `_pointAtTarget`) each call their own
restore; the first to finish drops protection while the other is still
capturing, so Handrail appears in the frame it was meant to be absent from.
*Fix:* refcount, idempotent restore.

**M3. The mock bridge ships in production.** `renderer/overlay.html` loads
`mock-bridge.js`, guarded only by `if (window.handrail) return`. If the real
preload ever fails, the app silently presents a fully working-looking overlay
with fabricated threads and a canned answer. Was a deliberate call ("ship what
was tested"); the review's argument against is stronger.
*Fix:* exclude from the packaged build in `scripts/package-win.js` and the
electron-builder `files` list.

**T4. `keyHint()` leaks a short key whole.** `src/main/store.js` —
`key.slice(0,9) + '••••' + key.slice(-4)` overlaps below 13 chars. With
`OPENROUTER_API_KEY=short` the hint is `Unknown · short••••hort`. The smoke
assertion only checks `/••••/` and passes.

**T5. `getKey()` deletes the key file on ANY throw.** `src/main/store.js` — a
transient decrypt failure (keyring not ready, malformed base64) is
indistinguishable from orphaned ciphertext, and the recovery is irreversible.
*Fix:* only unlink when a v1 `enc:'os'` record genuinely fails to decrypt.

**T6. `friendly()` misclassifies provider errors.** `src/main/turn.js` —
`/5\d\d/` matches "5000 tokens"; `/401/` matches "request 401829". These strings
are the only diagnosis the user ever sees.
*Fix:* word-boundary the codes, prefer `err.status`.

**M4. `watching` setting is half-wired.** Declared in `DEFAULT_SETTINGS`, has an
ipc branch, no UI, and `turn.js` never reads it. Now partly addressed (watching
is gated on `capture`), so either honour `watching` or delete it.

**T7. `firstSentence` truncates at an abbreviation.** "Use the crop tool, e.g.
the one in the left toolbar." → label reads "Use the crop tool, e.g." Minor, but
that label is the only instruction next to the arrow.

## Test gaps named by the review

`npm test` covers geometry and `providerOf` only. Untested and load-bearing:

- `turn.js` step transitions — `completeStep`, `reopenStep`, `_checkActiveStep`,
  the failure counter. The entire state machine.
- `llm.js` `respond()` shape handling — smoke stubs it out entirely, so no line
  of it runs in any test.
- `store.js` — corrupt-file recovery, key format migration, thread capping.
- `renderer/overlay.js` `renderProse`/`inline` — only exercised through a real
  Electron window.
- `capture.js` — no test file at all.

The specialists supplied ready-to-use `node:test` stubs for most of these; they
are in the agent output, not yet transcribed here.
