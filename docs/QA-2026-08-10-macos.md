## What was verified

- **The `[hidden]` regression is genuinely fixed.** `#key-lost` computes to
  `display: none` with the attribute present. This is the bug that put a banner
  reading "Windows regenerates its encryption store" on screen during a first
  run on a Mac, on every launch, because `.notice { display: flex }` outranked
  the UA rule for `[hidden]`. Verified in a real browser, not by reading CSS.
- **Provider detection, all shapes.** Driven through the real `input` handler:

  | Input | Chip | Field state | Continue |
  |---|---|---|---|
  | `sk-or-v1-` + 64 chars | OpenRouter | valid | enabled |
  | `sk-ant-…` | Anthropic | valid | enabled |
  | `sk-proj-…` | OpenAI | valid | enabled |
  | `AIza…` | Google | valid | enabled |
  | `not-a-key` | — | null | disabled |
  | empty | — | null | disabled |

  This is the fake-key test originally requested, run with no spend.
- **Accessibility.** Every button, input, switch and select carries a label,
  `aria-label` or placeholder. No unlabelled controls. No images without `alt`.
- **Console.** No errors originating in product code.

## Findings

### QA-001 — `onboarding.html` cannot be dev-previewed — Low, UX/DX

`overlay.html` loads `mock-bridge.js` at line 184; `onboarding.html` loads no
bridge at all. Opening it outside Electron leaves `window.handrail` undefined, so
`bridge.settings.get()` throws during module evaluation.

Impact is limited to developers, not users: the throw happens after `show(0)` and
after the navigation listeners are attached, so the flow is still walkable and
everything above was testable. But the onboarding screen is the one surface a new
user cannot avoid, and it is the only one that cannot be opened in a browser to
check.

*Repro:* serve the repo, open `/renderer/onboarding.html`, read the console.

*Not fixed — reporting only.* The fix is one `<script>` tag plus the setup
methods in the mock, which the mock already has (`requestScreenAccess` is stubbed
at `mock-bridge.js:213`).

### QA-002 — Dead vertical space on onboarding steps 1 and 2 — Low, Visual

At the window's own 760x620, content ends around y=330 and the footer sits at
y=580, leaving roughly 250px of empty panel. Not broken and not misleading,
just loose. Visible in `onboarding-step1.png` and `onboarding-step2.png`.

*Not fixed — a layout change is a design call, not a QA repair.*

## Non-findings — checked and cleared

- **"Antropic" in the key help text.** Reads as a misspelling in a downsampled
  screenshot. `document.getElementById('key-help').textContent` and the file
  itself both say **Anthropic**. A font-rendering artifact at small size, not a
  defect. Recorded so nobody "fixes" it later.
- **`design/tokens.css` 404.** An artifact of serving `renderer/` as the web
  root. The path is `../design/tokens.css`, which resolves correctly under
  Electron's `file://`. Gone once served from the repo root.

## Coverage this pass could not reach

Stated plainly rather than scored, because pretending otherwise is how the
two-instance bug survived an evening.

- **Retina.** This Mac drives one 1920x1080 panel at scaleFactor 1. The 2x
  coordinate path is exercised by unit tests over `geometry.js` and by nothing
  else. Untested on real hardware.
- **Multi-monitor and mixed DPI.** One display attached. `selectSource` and the
  aspect-ratio guard are unit-tested only.
- **Intel.** `Handrail-0.1.4.dmg` (x64) is built and never launched.
- **Live model round-trip.** The arrow pipeline was proven end-to-end with a
  known injected box: computed centre landed on the target exactly and the tip
  sat 14px off the control edge, matching `ARROW.tipGap`. The model's ability to
  find a ~40px Dock icon on a 1x display is a separate, unfixed limitation.

## Suggested next

1. Add the mock bridge to `onboarding.html` (QA-001) so the first-run screen is
   previewable. Small, and it closes the only untestable surface.
2. Borrow a Retina Mac before claiming Retina support in `PLATFORM.md`.
3. The repo has no linter and no type checker. Every quality signal comes from
   tests. Separate scope, but worth naming.
