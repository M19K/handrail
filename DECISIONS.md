# Decisions

Append-only. One line per decision: date — what was decided — why.
**Never rewrite an earlier line.** If a decision is reversed, add a new line saying so.

---

- 2026-08-01 — Build the product as a fork of OpenCluely rather than from scratch — ~60% of the plumbing (overlay, capture, streaming, windowing) is reusable; rewriting it would be wasted effort
- 2026-08-01 — Product named **Handrail** — what you grab when navigating unfamiliar terrain; communicates support without implying concealment
- 2026-08-01 — Target audience is **non-technical users** — evening the score for people who can follow instructions but can't diagnose failures
- 2026-08-01 — Drop the interview/DSA use case entirely — it is upstream's purpose, not ours, and frames the product around evasion
- 2026-08-01 — Treat upstream license as **Apache 2.0** — the LICENSE file governs; package.json (ISC) and README badge (MIT) are wrong
- 2026-08-01 — Do not use GitHub's Fork button; use a fresh repo with first commit = pristine upstream import — keeps our work legible as ours while attributing honestly
- 2026-08-01 — Use **OpenRouter** for both LLM and speech-to-text on a single key — no local Python/ffmpeg toolchain needed, and this machine has no CUDA GPU
- 2026-08-01 — Default model `google/gemini-2.5-flash`, STT `openai/whisper-1` — cheapest workable combination (~$0.42/hr of full voice+AI use)
- 2026-08-01 — Adopt **gstack** as the workflow spine — sprint order feeds output forward sequentially
- 2026-08-01 — Disable the **superpowers** plugin — competing planning/TDD/review methodology, would collide with gstack on the same requests
- 2026-08-01 — Keep the **playwright** plugin — its `_electron` API is the only viable QA automation path for an Electron overlay
- 2026-08-01 — Skip `greensock/gsap-skills` for now — an overlay needs motion restraint; CSS plus the animation trio suffices
- 2026-08-01 — Prioritise `apple-design` above its position in the original stack doc — macOS is a first-class target and its motion language suits a floating overlay
- 2026-08-01 — Handrail is a **desktop app only** — no web front end in scope
- 2026-08-01 — Cross-platform Windows **and macOS** is a hard requirement, not a nice-to-have
- 2026-08-01 — Apple Developer Program status confirmed **NOT enrolled** (free tier only; enrolment page shows "Select your entity type") — the remembered D-U-N-S belongs to an incomplete enrolment or another Apple ID
- 2026-08-01 — Ship macOS as an **unsigned .dmg** for v1 with the Gatekeeper workaround documented prominently — $99 is better spent elsewhere right now
- 2026-08-01 — Enrol in the Apple Developer Program **later**, as **Individual / Sole Proprietor** not Organization — faster verification (24-48h vs days/weeks), sufficient for non-App-Store distribution, and puts the author's own name on portfolio work
- 2026-08-01 — Signing is **configuration, not architecture** — adding it later requires one electron-builder config block plus a CI secret, so deferring costs nothing
- 2026-08-01 — **Cut voice/speech entirely from v1** — most complex subsystem, only feature with an unsolved macOS problem (system-audio loopback driver), ~$0.36/hr to run, and the use case is screenshot-driven
- 2026-08-01 — **Discard the entire existing UI** — no coherent workflow, no home/dashboard, structurally incoherent; full rework rather than incremental improvement
- 2026-08-01 — v1 scope is Windows + macOS (unsigned), screenshot and text driven, no voice
- 2026-08-01 — **Flagship use case is operating complex software** (Premiere, After Effects, Unreal, Excel) — "the best way to learn is by doing"; guided live over the real app beats watching a tutorial
- 2026-08-01 — Three UI states: collapsed pill → expanded bar → expanded answer; **expanded bar is the default on launch**
- 2026-08-01 — No separate dashboard app — the overlay expands into sections/side panels for settings, keys, and history
- 2026-08-01 — Screen capture **on by default**, with a toggle to disable — rejected letting the model decide, too unpredictable
- 2026-08-01 — Capture **full screen only**, on **whichever monitor the overlay currently sits on** — no region select, no window picker; move the overlay to change what it sees
- 2026-08-01 — Show a "screenshot captured" indicator but **no thumbnail preview** — redundant when capturing the whole screen
- 2026-08-01 — **Hybrid task model** — quick answers for generic questions, step tracking for genuinely multi-step tasks; requires intent classification
- 2026-08-01 — Checklist UI appears **only** for multi-step tasks — most prompts are generic, so always-on would be noise
- 2026-08-01 — **Visual cues on screen (arrows at real buttons) deferred to v1.1** but architecture must not foreclose it — it is the strongest differentiator
- 2026-08-01 — Threads behave like Claude chats: new thread on restart, auto-titled from first prompt, rename/delete, persist locally, search by name
- 2026-08-01 — All storage **local** (screenshots, keys, threads) — only the AI request leaves the machine; state this plainly in onboarding
- 2026-08-01 — **No local redaction** of sensitive on-screen content in v1
- 2026-08-01 — **Keep invisibility in full** — not the purpose, but useful and already built; Handrail can be used like Cluely/Pluely minus meeting recording
- 2026-08-01 — File attach exists to supply **reference material for the current task** (e.g. app documentation as PDF), working alongside screen capture — not a general file manager
- 2026-08-01 — Single API key field that **auto-detects provider** from key format — no dropdown, no provider selection
- 2026-08-01 — Design: take Cluely's restraint + Pluely's drag grip, thread panel and file attach; reject Pluely's navigational sprawl
- 2026-08-08 — /office-hours run in **Builder mode** (open source / portfolio), not Startup mode — goals are portfolio, personal use, and course, all builder goals
- 2026-08-08 — **The arrow is the demo moment** — the one thing legible in a single screenshot and the only feature neither Cluely nor Pluely has
- 2026-08-08 — **Arrow moves into v1** (reversing the earlier v1.1 deferral) — a portfolio piece whose headline ships later is a weak portfolio piece
- 2026-08-08 — **Spike the arrow first**, half a day, as a go/no-go gate — vision-model coordinate accuracy is the only genuine unknown; checklist-as-headline is the fallback
- 2026-08-08 — **Approach C: Spike-Led Rebuild** chosen over Strip-and-Reskin (A) and straight Renderer Rewrite (B) — same destination as B with the risk sequenced first
- 2026-08-08 — Keep the **main process**, delete **all four renderer windows**, rebuild as one overlay + panels; IPC contract redesigned alongside
- 2026-08-08 — **Honest framing on the install gap** — unsigned macOS requires a Gatekeeper bypass a non-technical user won't do; README states the real v1 audience and ships a first-class install guide rather than overclaiming
- 2026-08-08 — Design doc: `~/.gstack/projects/TechyCSR-OpenCluely/m19k1-main-design-20260808-205158.md`
- 2026-08-08 — Note: gstack project slug is `TechyCSR-OpenCluely` (from git remote) — changes when the repo is re-inited as Handrail; early artifacts live under the old slug
- 2026-08-08 — Arrow spike built as a **standalone Electron entry** (`spike/arrow/`), importing nothing from `main.js` or the four renderer windows — a go/no-go gate should leave zero cleanup debt if the answer is no
- 2026-08-08 — Vision model is asked for **normalised 0–1000 box coordinates** (Gemini's native `box_2d`, `[ymin,xmin,ymax,xmax]`), never pixels — normalised coords are resolution-independent, so `scaleFactor` never enters the coordinate math and the DPI problem is solved by construction rather than by a correction factor
- 2026-08-08 — Capture requests `display.size * scaleFactor` (native pixels), not DIP size — a 2x panel captured at DIP throws away half the linear detail the model needs to resolve a small toolbar button; scaleFactor affects capture *fidelity* only, never coordinates
- 2026-08-08 — Capture matches the `desktopCapturer` source to the display by **`display_id`**, with the size heuristic as fallback only — the existing heuristic in `capture.service.js` silently picks the wrong monitor when two displays share an aspect ratio
- 2026-08-08 — Overlay window must `setBounds()` **after** construction and only then `setResizable(false)` — Windows clamps a non-resizable window to the work area, which costs the taskbar strip; pointing at a taskbar icon is a legitimate first step in a guided task
- 2026-08-08 — Tests run on **Node's built-in runner** (`node --test`), no framework and no new dependency — the repo had no harness and picking one is not the spike's call; this is also the future home for the 51 orphaned tests
- 2026-08-08 — The spike **self-captures its own result** to a PNG after drawing — the claim under test is "the arrow is on the button", which only a picture can settle; doubles as the portfolio artifact
- 2026-08-08 — Arrow marker uses a **dual-stroke** treatment (dark outer, bright inner) — Handrail must stay legible over both near-black UIs (Premiere, Unreal) and near-white ones (Excel)
- 2026-08-08 — **Re-sequenced: design before finishing the arrow spike** — the spike's remaining half is blocked on the user's API key, design is blocked on nothing, and the project had produced nothing visible to look at; reverses the spike-first ordering for scheduling reasons only, not on the merits
- 2026-08-08 — Renamed the approved gstack doc from "design doc" to **"build plan"** in all project docs — it contains sequencing and architecture, no pixels, and the word "design" was read as "the UI is done"
- 2026-08-08 — **`ui-ux-pro-max` skill's search script cannot run on this machine** — it requires Python and this machine has only the Microsoft Store alias stub; its CSV data under `data/` is read directly with grep instead. Assume the same for any other Python-backed skill among the 72 installed
- 2026-08-08 — **The signature colour is the primary brand decision**, not a downstream one — the on-screen arrow is the product's most legible artifact, so the arrow's colour becomes the brand whether or not it is treated as one
- 2026-08-08 — **Blue, red and amber ruled out as the signature colour** — blue collides with selection/focus chrome in essentially every host app; red and amber carry error and warning semantics that would misrepresent a guidance cue
- 2026-08-08 — Three visual directions put up for choice: **A Calm Instrument** (dark glass, mint #2FD9A8), **B Guide** (light card, violet #6B4DE6), **C The Rail** (edge-docked, orange #FF7A45) — board at `design/directions-v1.html`
- 2026-08-08 — **DIRECTION A "Calm Instrument" CHOSEN.** Signature mint `#2FD9A8`, dark translucent glass, floating overlay, tight compact type. Rejected B (light card) and C (edge-docked rail) — C's concept was liked but a permanently edge-anchored window was not
- 2026-08-08 — **Main process rewritten rather than edited** — upstream's `main.js` (1,990), `window.manager.js` (1,839), `llm.service.js` (1,710) and `speech.service.js` (2,098) were interview-era code that would have cost more to unpick than to replace. New: `src/main/{store,llm,capture,turn,windows,ipc,prompts}.js`. ~15,100 lines deleted, ~1,900 written
- 2026-08-08 — **One model call decides answer-vs-task, not a separate classify pass** — a classify-then-act pass would double latency and cost on every prompt to save nothing; the model reads the screenshot either way and is capable of choosing its own output shape
- 2026-08-08 — **Frame comparison samples compressed PNG bytes rather than decoding pixels** — decoding a frame every 600ms is real CPU on a machine the user is trying to work on, and the question is only "did anything change", not "what changed"
- 2026-08-08 — **Handrail hides its own windows before every capture** — otherwise the overlay appears in the screenshot and the model starts describing Handrail's own previous answer back to the user
- 2026-08-08 — **API key encrypted at rest via `safeStorage`** (DPAPI / Keychain), with an announced plaintext fallback where no keyring exists — a silent fallback that pretends to be encrypted is worse than no encryption
- 2026-08-08 — **Onboarding verifies the key with a real request**, not just a shape check — a typo caught at setup costs three seconds; the same typo found later shows up as a failed answer mid-task with no hint that the key was the problem
- 2026-08-08 — **Provider detection is duplicated in the renderer** for instant per-keystroke feedback, with main remaining authoritative — a round trip per keystroke would make the field feel broken, and a mismatch can only ever be cosmetic
- 2026-08-08 — **`window-all-closed` ordering bug found by the smoke test and fixed** — closing onboarding before creating the overlay left zero windows open for an instant, which quits the app on Windows. Create the replacement, then close
- 2026-08-08 — **Navigation is blocked at the `web-contents-created` level** — a prompt-injected link in a model answer must not be able to turn the overlay into a browser pointed at somebody else's site
- 2026-08-08 — **`scripts/smoke.js` boots the real modules, real preload and real IPC and screenshots every window** — the renderer harness proves the UI against a mock; this proves the half a mock cannot, where failures are silent because a window that fails to boot looks identical to one that is merely empty
- 2026-08-08 — **A dedicated panic hotkey** (`Ctrl/Cmd+Shift+Esc`) cancels everything and hides the overlay — if it is ever stuck visible during a screen share, hunting for the right window is not an option
- 2026-08-08 — **The overlay shows with `showInactive()`** — taking focus from the app the user is being taught is exactly wrong for an assistant sitting on top of it
- 2026-08-08 — **IPC contract redesigned and written down first** (`docs/IPC.md`) — upstream had two overlapping bridges (`electronAPI` ~90 methods, `api` a second channel allowlist) and 15 separate `onXxx` listeners. Replaced by one namespaced `window.handrail` and **one event stream** (`onTurn`) carrying tagged events, so fifteen listeners became one `switch`
- 2026-08-08 — **The renderer owns no truth** — threads, steps, settings and keys live in main; the renderer paints what it is told and reports what the user did
- 2026-08-08 — **The API key never crosses the bridge after setup**; only a masked hint (`sk-or-v1-••••2f9c`) comes back. A renderer that cannot read the key cannot leak it
- 2026-08-08 — **Screenshots never reach the renderer** — captures go straight from the capture service to the provider, so there is no image data to cache, log or accidentally render
- 2026-08-08 — **The arrow is a turn event (`point`), not a separate subsystem** — same lifecycle, cancelled by the same `cancel()`. Two lifecycles would eventually drift, and a stale arrow pointing at nothing is this product's worst failure
- 2026-08-08 — **The overlay window resizes to its content** rather than being one large transparent window with click-through hit-testing — hit-testing means tracking the cursor to decide what is clickable, which is fragile on both platforms
- 2026-08-08 — **Renderer is built against a mock IPC bridge** (`renderer/mock-bridge.js`) that installs itself whenever the real preload is absent — the renderer could therefore be built, driven through every state and reviewed by eye before main was rewired, instead of the two landing together untested
- 2026-08-08 — **`renderer/dev.js` scripted screenshot harness** (`npm run dev:renderer`) drives all nine states and writes a PNG of each — the only honest way to claim a UI works, and a cheap regression check afterwards
- 2026-08-08 — Answer markdown is rendered by a **~30-line subset renderer using `createElement`/`textContent`, not a markdown library** — answers are short instructions, and no model output should ever reach `innerHTML`
- 2026-08-08 — Step text uses **three weights of legibility, not two** — done steps stay readable (history), the active step is primary and medium, unreached steps recede. Only one step is ever the instruction
- 2026-08-08 — **LOGO CHOSEN: Mark C4 with the grip** — a handrail drawn in one continuous stroke (flat, then turning down into its own post) with a mint grip on the flat section. Canonical geometry, files and usage rules in `design/brand/README.md`
- 2026-08-08 — Diagnosis that drove the logo revision: **symmetry was the bug, not stroke count** — three equal strokes evenly spaced on a symmetrical grid resolve into a table or a pi at 16px. Every variation broke the symmetry a different way
- 2026-08-08 — **The grip's position is a variable, not decoration** — it slides along the flat section (`cx ∈ [5, 14.5]`) as steps complete, so the logo doubles as the product's progress indicator. It never enters the curve, because a hand does not grip a corner
- 2026-08-08 — **A separate `mark-16.svg` exists and must be used at ≤20px** — at 16px the 2.6 stroke lands between pixels and the grip loses its edge; scaling the 24px file down is a defect, not a shortcut
- 2026-08-08 — The app icon is centred on the mark's **ink bounding box, not its grid** — the artwork spans x 1.7–20.3 / y 5.6–21.3, so grid-centring would push it low and left; invisible in a design tool, obvious in a dock
- 2026-08-08 — **The grip is the same mint as the on-screen arrow, and may never be recoloured** — it is what connects the logo to the product's headline feature
- 2026-08-08 — **Step completion is hybrid but weighted to watching** — manual tick exists as an escape hatch, not as the mechanism. Governing assumption stated by the user: *the user will not click done*; someone struggling through Premiere will not stop to do bookkeeping for us
- 2026-08-08 — **Each step carries its own visual done-condition, generated at plan time** — turns verification from an open-ended "where are we?" into a cheap targeted yes/no. This is the load-bearing decision that makes watching affordable
- 2026-08-08 — **Never poll on a timer.** Check is gated by: local downscaled frame diff (free) → ~1.2s quiet debounce (free) → one small vision call → ~4s rate cap. A user who is reading and not touching anything costs nothing
- 2026-08-08 — Completion checks use a **downscaled capture**; only arrow-locating needs native resolution — a yes/no needs far less detail than finding a control
- 2026-08-08 — **Detecting a wrong move is the most valuable outcome, not an edge case** — it is the reason the product exists; gentle correction, never an error state
- 2026-08-08 — **Advancing a step is always soft and reversible**, and after three failed checks Handrail stops checking and surfaces the manual tick — failing quietly beats nagging
- 2026-08-08 — **Screen-watching is visible and switchable in settings** — it spends the user's money and sees their screen; hiding it would be indefensible
- 2026-08-08 — The **checklist advancing on its own is the second demo moment** after the arrow — noted so the renderer treats that transition as a designed moment, not an incidental state change
- 2026-08-08 — **Onboarding is a one-time real window, not an overlay side panel** — closes the open question in PRODUCT.md. It asks the user to paste a secret and makes a privacy promise; neither belongs in a 30px strip
- 2026-08-08 — Onboarding is **three steps: what Handrail does → API key → screen-recording permission**. No account, no email
- 2026-08-08 — The **capture indicator is a transient chip** in the bar (~1.5s), not a persistent badge — it confirms an event, then stops consuming space
- 2026-08-08 — **Mint is reserved for exactly three things**: the arrow, the current step, the focus ring. Status colours (danger `#FF6B5B`, warning `#FFB84D`) are separate tokens — the accent means "look here", status means "something happened", and conflating them makes the overlay lie
- 2026-08-08 — **The arrow's mint stroke may never be drawn without its dark casing** — mint on white is ~1.9:1; the casing means the marker carries its own contrast rather than assuming a ground. Encoded as a token pair, not left to the renderer
- 2026-08-08 — **One arrow at a time** — two arrows is a diagram, not an instruction
- 2026-08-08 — Motion spec: **150ms in, 90ms out, ease-out** — exits faster than entrances, because leaving should feel like getting out of the way
- 2026-08-08 — Settings copy is written as **things you do, not features you have** ("Capture my screen", not "Screen capture module") — the audience is non-technical
- 2026-08-08 — Design tokens live at `design/tokens.css` in three layers (primitive → semantic → component); **no component may contain a raw hex value**
- 2026-08-08 — Consequence of choosing A: the **three-state floating model in PRODUCT.md stands unchanged** — collapsed pill → expanded bar → expanded answer, draggable anywhere
- 2026-08-08 — Established before the pick: **look is cheap to change later, shape is not** — colour/type/radius/surface live in tokens and reskin in hours; floating-vs-docked decides the window model, positioning, multi-monitor logic and the IPC contract. A-vs-C was an architecture decision wearing a visual costume
- 2026-08-08 — Direction C was presented as an **explicit challenge to the locked three-state model** (collapsed pill → expanded bar → expanded answer) — an edge-docked rail is derived from the product's own name and avoids occluding the app being taught; choosing it means reversing that decision deliberately

- 2026-08-09 — **Python 3.13.15 installed** (winget, user scope) — several gstack skills are Python-backed and were silently unusable; `ui-ux-pro-max` search now runs
- 2026-08-09 — **Ran gstack `/review` with three specialist agents** — 28 findings on a diff nobody but the author had read. Recorded in `docs/REVIEW-2026-08-09.md` rather than fixed in one pass, because 20 of them deserve individual verification
- 2026-08-09 — **`.env` no longer overrides the stored key in a packaged build** — dotenv ships inside the app, so a `.env` beside the executable silently rerouted every screenshot through another account. Gated on `!app.isPackaged`
- 2026-08-09 — **`hr:setup:*` verifies the sender is the onboarding window** — one preload serves both windows, so the overlay (which renders model output) could overwrite the API key
- 2026-08-09 — **`openExternal` takes a destination NAME, not a URL** — the https check made it a general "open any website" primitive reachable from the overlay
- 2026-08-09 — **Releases are built in CI, not locally** (`.github/workflows/release.yml`) — electron-builder cannot run on this machine and a macOS .dmg needs a Mac; GitHub runners solve both for free. `scripts/package-win.js` stays as the local Windows fallback
- 2026-08-09 — **Distribution is GitHub Releases, unsigned, with the SmartScreen/Gatekeeper steps documented in the release body** — signing is $99/yr per platform and deferred
- 2026-08-09 — **Generated icons are committed** (`build/icon*.png`, `.ico`) — CI needs them to package and regenerating there would mean running Electron headless to rasterise an SVG

- 2026-08-09 — **`this.epoch` is now consumed, not just bumped** — `_pointAtTarget` captures it and refuses to draw or emit if it moved during its awaits. Closes the failure our own comments called the worst this product has: an arrow appearing after the user hid Handrail
- 2026-08-09 — **The renderer sends `threadId` with every `hr:ask`** — main cannot know which thread is open, and guessing "most recently updated" wrote follow-ups into the wrong conversation. Same class of bug as the renderer minting `turnId`: the renderer owns what only the renderer knows
- 2026-08-09 — **Every path that clears the arrow also emits `{type:'point', rect:null}`** — the "Pointing at it on your screen" badge was driven by success only, so it outlived the arrow on every failure, on dismiss and on the 45s dwell timer
- 2026-08-09 — **A checklist main has stopped watching says so in the list itself** (`offplan`, `unwatched`) — silence left something that looked live and would never advance
- 2026-08-09 — **The watch tick validates which display it captured** — `captureDisplay` now returns `matched: 'display_id'|'size'|'fallback'` and watching stops on `fallback`. Source selection was extracted as a pure `selectSource` so the rule is testable without Electron
- 2026-08-09 — **A failed key decrypt no longer deletes the key file** — the old code could not tell a permanently orphaned blob from a keyring that was not ready yet, and turned a transient failure into permanent loss. `saveKey` overwrites anyway, so deleting bought nothing
- 2026-08-09 — **`mock-bridge.js` is excluded from every packaged build**, and `overlay.js` fails loudly when the bridge is missing — a shipped mock means a broken preload presents a convincing fake app full of invented data. Reverses the earlier "ship what was tested" call; the review's argument is stronger
- 2026-08-09 — **Cancel aborts on the wire** — an `AbortController` is threaded through `llm` into `fetch`. Escape used to discard the reply and leave the request running and billed
- 2026-08-09 — **`excludeFromCapture` is refcounted** — a watch tick and an arrow locate overlap, and the first to finish dropped capture protection while the other was still capturing
- 2026-08-09 — **Repo is `github.com/M19K/handrail`, public, created fresh rather than forked** — `7909792` is the first commit on GitHub, so the attribution story holds and the work is not buried in upstream's network graph
- 2026-08-09 — **electron-builder bumped 24 → 26** — 24.x cannot write a .dmg volume's `.DS_Store` on the macOS the GitHub runners now use, and died at the packaging step. Windows built fine on the same run, which is what located the fault
- 2026-08-09 — **`package-lock.json` regenerated** — it had drifted from `package.json` (rimraf missing, the whole removed speech stack still present), so `npm ci` failed on both runners. Nothing had noticed because every local install used `npm install`
- 2026-08-09 — **v0.1.0 is left as a DRAFT release** — the workflow drafts on purpose so a human reads the notes before it goes public, and nobody has yet opened the macOS build on a Mac
- 2026-08-09 — **Authorship is recorded in three places, not one**: a `NOTICE` file naming Maaz Kazi as author and listing exactly what is original, a copyright + SPDX header on all 38 original source files, and the README's authorship section. Apache-2.0 keeps copyright with the author; what it grants is a licence to use, on condition the notices survive. Upstream published no NOTICE, so ours carries only our own attribution plus the required credit to OpenCluely
- 2026-08-09 — **The project stays Apache-2.0 and cannot be made proprietary** — it derives from Apache-2.0 code, and s4 requires the licence to travel with any copy. The original work is still owned by its author; the licence is the condition of use, not a transfer
- 2026-08-09 — **`LICENSE` and `NOTICE` are packaged inside the app**, not just the repo — Apache-2.0 s4 requires both to travel with a distributed copy, and the release ships an installer, not a checkout
- 2026-08-09 — **`/qa` runs through Playwright `_electron`, not a browser** — Handrail has no URL. `_electron` launches the real binary, so it covers what `scripts/smoke.js` structurally cannot: boot, window lifecycle, the single-instance lock, position persistence, and what a person sees when the model call fails. Both suites are kept; they cover different halves
- 2026-08-09 — **`playwright-core`, not `playwright` or `@playwright/test`** — driving Electron needs `_electron` and nothing else, and the full package downloads three browsers on install that CI would then download again for nothing
- 2026-08-09 — **`npm test` stays pure and fast; `npm run qa` is the Electron suite** — the unit tests gate the release in CI and must not need a display or a binary
- 2026-08-09 — **Launching Handrail again SHOWS it; only the tray icon and the hotkey toggle** — `second-instance` called `toggleOverlay()`, so double-clicking the desktop shortcut while the overlay was open made it disappear. Launching is not a switch
- 2026-08-09 — **v0.1.1 shipped through a real PR** ([#1](https://github.com/M19K/handrail/pull/1)) rather than straight onto main — `/ship` refuses to run on the default branch, and on a portfolio repo a reviewable PR is worth the few extra minutes. The QA work itself had already been pushed to main, so the PR body says so plainly instead of claiming a diff it does not contain
- 2026-08-09 — **`VERSION` and `CHANGELOG.md` now exist** — the project had a tagged release and no record of what was in it, which makes release notes the only history and the next diff the only way to find out what changed
- 2026-08-09 — **Releases stay drafts until a human publishes them** — nobody has opened the macOS build on a Mac, and publishing is public and awkward to walk back. v0.1.1 supersedes v0.1.0 entirely; tidying that up is the user's call
- 2026-08-09 — **`--text-tertiary` is 0.46 alpha, not 0.44** — 0.44 measured 4.37:1 against the base surface, just under WCAG AA, and that token carries every settings explanation and the key hint. 0.46 measures 4.66:1 and is invisibly different. Do not lower it back
- 2026-08-09 — **The polish pass fixed defects and refused to redesign** — the type scale being small for a non-technical audience, the 3.11:1 placeholder and the 17–22px touch targets are all real observations, and all three are deliberately left alone because changing them changes the product rather than repairing it. They are recorded in `.gstack/qa-reports/design-audit-handrail-2026-08-09.md`
- 2026-08-09 — **Fixed sleeps in `scripts/smoke.js` are replaced by `settled()`** — the pointing checks raced about one run in four because the capture toggle's async round trip was never waited for, and the failure read as the pointing feature being broken. Poll a condition; never guess at a duration
- 2026-08-09 — **Default model is `google/gemini-3.5-flash`, not the lite tier** — measured, not assumed.
